# Viewer fixtures

Committed v1-schema journals generated by the in-repo example kernels
(`examples/viewer_kernels/`). They feed the viewer distiller tests and the
committed demo (`viewer/demo/view.html`).

Why these exist (docs/TRACKED_LIBRARY_PLAN.md, Phase 6): the historical AMP
fixture journals are pre-v0.3 — no `id` field — so they cannot feed the DAG
view, and regenerating them requires a cluster + Kokkos. These fixtures are
self-contained: plain C++17, one driver, no dependencies.

## Layout

- `demo/journal.jsonl` — one monolithic run: 9 units × 16 samples.
- `demo_sharded/journal-000.jsonl`, `demo_sharded/journal-001.jsonl` — the
  **same run** split into two `--sample-offset`/`--sample-count` shards
  (samples 0–7 and 8–15). Shard ids carry shard-local `#<counter>`
  suffixes (docs/STREAMING.md), so the files are not byte-slices of the
  monolithic journal — but every grouping key is shard-invariant, and a test
  asserts the distiller produces an **identical view model** from either
  layout.

## Feature-coverage matrix

Every render path in the viewer template is exercised by these fixtures
(`tools/tests/test_view.py` asserts each row, so coverage cannot silently
regress):

| Feature | Producing unit(s) |
|---|---|
| `local_cancellation` class | `cancellation` |
| `cancellation_cascade` class + cascade chains | `cancellation`, `alternating_series`; `second_difference` (two-line span) |
| `log_near_root` class | `naive_variance`, `log_sum_exp`, `complex_logdiv` |
| `atan2_saturation` class (all-capped region) | `range_overflow` (inf−inf line) |
| `stable` class | several units |
| `cap` causes `log` / `atan2` / `sin` / `cos` / `nan` | `log_sum_exp`, `polar_phase`, `range_overflow` |
| `exact_tie` marker | `kahan` |
| float range-guard violation | `range_overflow` |
| non-finite sentinels (`"inf"`, `"nan"`) | `range_overflow` |
| `line=` statement regions | `cancellation`, `naive_variance`, `alternating_series`, `cascade` line scopes |
| `at` regions (located named calls) | every unit |
| operator-form records (empty `at`, anonymous `@?#` ids) | `complex_logdiv` (the loc-less real ops inside `Complex operator/`) |
| multi-function units (call edges, swimlanes) | all except `range_overflow` |
| complex decomposition rollup + `opaque` records | `complex_logdiv` |
| pathological first-order bound (extreme-value formatting) | `kahan`, `alternating_series` |

Not producible on IEEE hosts without flush-to-zero: the `add_uflow` /
`sub_uflow` / `fma_uflow` cap causes (see docs/SCHEMA.md) — the template
treats unknown/unfixtured cap causes generically, per the schema's open-set
rule. `cap="log1p"` is likewise not reachable with these kernels.

## Regenerating

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Debug && cmake --build build -j --target gen_viewer_fixtures
./build/gen_viewer_fixtures --out viewer/fixtures/demo/journal.jsonl \
    --sample-offset 0 --sample-count 16
./build/gen_viewer_fixtures --out viewer/fixtures/demo_sharded/journal-000.jsonl \
    --sample-offset 0 --sample-count 8
./build/gen_viewer_fixtures --out viewer/fixtures/demo_sharded/journal-001.jsonl \
    --sample-offset 8 --sample-count 8
```

A single-sample drill-down slice (what the viewer's "rerun" recipe points
at) is e.g.:

```bash
./build/gen_viewer_fixtures --unit cancellation --sample-offset 7 --sample-count 1 \
    --out /tmp/cancellation_s7.jsonl
```

**Portability note:** the committed journals were generated on macOS/arm64.
The kernels call libm (`exp`, `log`, `sin`, `atan2`, `hypot`), whose last-bit
results differ across platforms, so regenerating on another OS/arch produces
journals that differ in low decimal digits (structurally identical). Within
one machine the driver is bit-reproducible, and chunked runs are
byte-identical to monolithic ones (`viewer_chunk_byte_equality` ctest).
Regenerate all fixtures (and the demo HTML) together, on one machine.
