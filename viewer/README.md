# Viewer (`tracked-view`)

A zero-dependency, single-file static HTML viewer for Tracked journal runs.
Two views over one run:

1. **DAG view** — unit → function → region graph with precision telemetry
   (node color = signal class, always paired with a text chip and a legend;
   badges for range-guard violations / saturation caps / exact ties; edges =
   region dataflow rolled up to function calls, plus cascade-chain spans),
   with a per-sample **op-level DAG** as click-through drill-down.
2. **Actionable report** — ranked hotspot cards plus the **decision ledger**
   (every classification verdict, saturation cause, and range-guard reason
   that previously died inside report JSON).

Design constraints (ratified, `docs/TRACKED_LIBRARY_PLAN.md` Phase 6):

- **No npm, no build step**: one self-contained `view.html` (hand-rolled
  SVG/HTML, CSS custom properties, light + dark). Works from `file://`;
  no fetch, no CDN, no external fonts.
- Fed by a **distiller** (`tracked-view`, part of `tools/`) that reduces a
  run directory to a small view-model JSON and injects it into the HTML
  template (`tools/tracked_tools/view/template.html`).

## Usage

```bash
pip install -e tools
tracked-view viewer/fixtures/demo -o view.html          # run dir (*.jsonl globbed)
tracked-view a.jsonl b.jsonl -o view.html                # explicit shard files
tracked-view run/ --json view_model.json -o view.html    # also dump the model
```

`tracked-view` accepts a run directory (every `*.jsonl` inside, sorted) or
explicit journal paths. Multiple journals are treated as shards of one run
and must obey the shard-disjointness precondition of `docs/SCHEMA.md` —
**validated**: the distiller hard-fails when the same non-empty sample
scope appears in more than one input (or reappears non-contiguously inside
one input), and emits a ledger warning when unscoped records show up in a
multi-journal read (unscoped units are excluded from the shard-invariance
guarantee below). `--legacy` reads pre-v1 headerless journals and `--predict
name=u` adds prediction target formats, exactly as in `tracked-reduce`;
`--saturation-cap X` (a `tracked-view` flag over the same `ReducerConfig`
seam) overrides the 1/u gate for non-`double` journals.

## Fixtures (`viewer/fixtures/`)

Committed v1-schema demo journals generated by the in-repo example kernels
(`examples/viewer_kernels/`) — the pre-v0.3 AMP fixture journals have no
`id` field and cannot feed the DAG view, and the AMP regen script needs a
cluster + Kokkos. See `viewer/fixtures/README.md` for the regeneration
commands and the **feature-coverage matrix** (every render path the
template has — classes, cap causes, ties, range violations, nonfinite,
chains, opaque, complex rollup, multi-function units — is exercised by the
fixtures and asserted by a test; the `*_uflow` cap causes are unreachable
on IEEE hosts without FTZ and are documented as permanently fixture-less).
`demo/` is a monolithic run; `demo_sharded/` is the same run split into two
`--sample-offset`/`--sample-count` shards.

## The view model (internal contract)

`tracked-view --json` emits the view model: the single JSON object the HTML
template renders. It is a **private contract between the distiller and the
template bundled in the same `tracked-tools` version** — unlike
`docs/SCHEMA.md` it carries no cross-version stability promise; the
`view_model_schema` field exists so a template can refuse a model it does
not understand.

**Shard invariance.** Every field *outside the `provenance` block* is
invariant under re-sharding of a fully-scoped run: `distill(monolithic) ==
distill(shards)` exactly, and a test enforces it on the committed fixture
pair. What makes that true (each item erases a shard-varying artifact of
the id `#<counter>` suffixes, per `docs/STREAMING.md`):

- drill-down operands are **batch-local integer indices**, never raw ids;
- literal leaves normalize to `_lit@<file>:<line>~<k>` where `k` is the
  callsite's occurrence ordinal within the sample batch (emission order is
  shard-invariant), so distinct literals from one callsite stay distinct;
- cascade chains are **structurally deduped** — grouped by (unit, sorted
  span set, ops signature) with a count and max-severity per group; the
  reducer's per-(sample, victim) `chain_id` (which hashes a raw id) is
  dropped;
- every collection has a canonical order (units by name; regions,
  functions, variables by key; edges by (src, dst); chain groups by span
  set; hotspots by severity desc with (kind, unit, location) tie-break);
  JSON is serialized with sorted keys, so equality is byte-equality.
- the drill-down sample choice is argmax batch `max_rel_err`, ties broken
  by lexicographically smallest sample scope key.

The `provenance` block (`journals` basenames, fixed `generator` string) is
excluded from the guarantee and from the equality test. No version string
is embedded anywhere in the output, so the committed demo build is
byte-stable across tool releases until the template or fixtures change.

```jsonc
{
  "kind": "tracked_view_model",
  "view_model_schema": 1,
  "provenance": {"generator": "tracked-tools", "journals": ["journal.jsonl"]},
  "legacy": false,                    // true = --legacy read
  "library_versions": ["1.0.0"],      // from headers; [] in legacy mode;
                                      // >1 entry = skew (ledger row)
  "config": { /* ReducerConfig thresholds + prediction formats used */ },
  "totals": {
    "records": 0, "samples": 0, "units": 0,
    "no_id_records": 0,
    "nonfinite_records": 0            // null in legacy mode (not measurable)
  },
  "units": [
    {
      "name": "cancellation",         // integral= scope value ("" = unscoped)
      "samples": 16,
      "records": 112,
      "class_counts": {"local_cancellation": 1, "stable": 2},
      "max_rel_err": 0.6,             // worst region/chain severity in unit

      // unit -> function -> region hierarchy.  A region's function is:
      //   at-keyed region -> the at's own file:function;
      //   line=-keyed region -> modal at-function over its records with
      //     non-empty at (lexicographic tie-break), which MAY live in a
      //     different file than the region (grouping is by function key,
      //     never by file nesting);
      //   otherwise -> the "(unattributed)" pseudo-function.
      "functions": [
        {"key": "examples/viewer_kernels/kernels.hpp:cancellation_check",
         "file": "examples/viewer_kernels/kernels.hpp",
         "name": "cancellation_check",
         "regions": ["examples/viewer_kernels/kernels.hpp:cancellation_check:61"]}
      ],
      // Region kind is decided STRUCTURALLY (from which source produced the
      // key), never by re-parsing the string: "line" = line= scope value
      // (file:line), "at" = located call (file:function:line), "" = neither.
      "regions": [
        {"key": "examples/viewer_kernels/kernels.hpp:cancellation_check:61",
         "kind": "at", "file": "examples/viewer_kernels/kernels.hpp",
         "line": 61,
         "function": "examples/viewer_kernels/kernels.hpp:cancellation_check",
         "signal_class": "local_cancellation",
         "note": "local cond 1.82e+15 exceeds 1e15 (|a-b|->0)",
         "n": 16,                      // flop weight (records over all samples)
         "ops": {"sub": 16},
         "max_cond": 1.82e15,
         "gate_a_count": 0,            // reducer's NUMERIC 1/u gate (parity)
         "cap_counts": {"log": 4},     // v1 branch-authoritative causes; the
                                       // ledger flags a region where the two
                                       // disagree (e.g. a float-T journal).
                                       // null in legacy mode
         "exact_tie_count": 0,         // null in legacy mode
         "nonfinite_count": 0,         // records with non-finite val/cond/
                                       // rel_err; null in legacy mode
         "max_rel_err": 0.6, "p50_rel_err": 0.1, "p99_rel_err": 0.6,
         "rel_err_hist": {"buckets": {"-1": 12, "0": 4}, "total": 16},
         "zero_rel_err": 0,            // records with rel_err == 0 (exact),
                                       // which LogHist cannot bucket
         "max_amp": 1.0, "max_sensitivity": 1.82e15,
         "predictions": {"float": 1.1e8},   // predicted_rel_err_if_<fmt>
         "abs_val_min": 1.8e-15, "abs_val_max": 2.0,
         "range_ok": true,             // value_range_ok_for_<config.range_name>
         "region_local_vars": ["a", "b"]}
         // optional: "rung" (string) — reserved for the AMP adapter
         // fast-follow; rendered as a chip when present.
      ],
      // region -> region dataflow (operand produced in src consumed in dst,
      // src != dst), aggregated over samples; the function-call rollup and
      // the edges table are derived from these in the browser
      "edges": [{"src": "examples/viewer_kernels/kernels.hpp:guarded_sum:53",
                 "dst": "examples/viewer_kernels/kernels.hpp:cancellation_check:61",
                 "n": 16}],
      // structural chain groups (see above), not per-sample records
      "chains": [
        {"spans": [{"file": "kernels.hpp", "line_start": 61, "line_end": 61}],
         "ops": {"sub": 16}, "count": 16,          // samples in this group
         "max_rel_err": 0.6, "max_cond": 0.0, "max_sensitivity": 1.0,
         "predictions": {"float": 6e-8}, "range_ok": true,
         "region_local_vars": ["a"]}
      ],
      // named inputs only: ids present in prov_vars (sources) or
      // prov_consts (constants).  Literal and opaque-fn leaves are excluded
      // (per-sample ids; not actionable inputs).
      "variables": {
        "a": {"is_source_var": true, "max_sensitivity": 1.82e15,
              "max_amp": 1.82e15, "n_samples": 16,   // samples consuming it
              "predictions": {"float": 1.1e8}}
      },
      // click-through drill-down: the unit's argmax-rel_err sample, op-level
      "drilldown": {
        "sample_scope": "integral=cancellation/sample=7",
        "sample": "7",                 // sample= scope value if present
        "max_rel_err": 0.6,
        // null unless the unit is named and sample= is decimal (the
        // template hides the rerun affordance when null)
        "rerun": "--unit cancellation --sample-offset 7 --sample-count 1",
        // nodes in emission (= a valid topological) order; "in" entries:
        // int = index of an EARLIER node, string = leaf key.  For
        // op == "opaque", in[0] is the external fn_name label (metadata,
        // not an operand) and is stored as "label", with only real
        // operands in "in".  val/cond/rel_err are numbers, or the v1
        // sentinel strings "nan"/"inf"/"-inf" verbatim (never the reducer's
        // alarm-direction clamp — that is aggregation policy, not display
        // data).
        "nodes": [
          {"op": "sub",
           "region": "examples/viewer_kernels/kernels.hpp:cancellation_check:61",
           "in": [0, "a"], "val": 1.8e-15, "cond": 1.1e15, "rel_err": 0.24,
           "cap": null, "exact_tie": false}
        ],
        "sources": ["a", "b"]          // leaf keys referenced by nodes
      }
    }
  ],
  "report": {
    // ranked across units: regions and chain groups interleaved, severity
    // (max_rel_err) desc, capped at the top 20 (the model records the
    // total).  A cancellation_cascade region whose line is covered by a
    // chain group in the same unit is skipped here (the chain group is its
    // localized replacement, per reduce/core.py) but stays in units[].
    "hotspots_total": 4,
    "hotspots": [
      {"rank": 1, "unit": "cancellation", "kind": "region",
       "location": "...kernels.hpp:cancellation_check:61",
       "signal_class": "local_cancellation", "note": "...",
       "metrics": { /* region/chain metric subset incl. digits_lost */ }}
    ],
    // every verdict with its reason; run-level facts first.  Rows may carry
    // an optional free-form "source" (reserved for the AMP adapter).
    "ledger": [
      {"unit": "*", "subject": "run", "verdict": "nonfinite_records",
       "detail": "48 records carried non-finite val/cond/rel_err ..."},
      {"unit": "cancellation",
       "subject": "...kernels.hpp:cancellation_check:61",
       "kind": "region", "verdict": "local_cancellation",
       "detail": "local cond 1.82e+15 exceeds 1e15 (|a-b|->0)",
       "range": "ok", "caps": {}, "exact_ties": 0}
    ]
  }
}
```

Notes on deliberate choices:

- **Regions drop `prov_vars`** (the transitive union dominates report size at
  AMP scale); `region_local_vars` — the region-scoped named inputs — are kept.
- **Size bounds** (AMP-scale run, per the plan's appendix): regions and
  variables are bounded by distinct locations/names; chains collapse from
  264k per-sample records to structural groups (≈ distinct span sets);
  hotspots cap at 20; ledger rows = regions + chain groups + run rows;
  drill-down = one sample slice per unit (~930 records/sample at AMP scale
  ⇒ ~1 MB per 21-unit run). Nothing scales with sample count.
- **Classification is the reducer's, unchanged** (`reduce/core.py` —
  thresholds, the numeric gate-a test, amp/sensitivity, chain extraction).
  The distiller runs its own streaming loop (it needs per-record cap/tie/
  nonfinite tallies, dataflow edges, and header metadata that the reducer's
  aggregation discards) but imports every policy helper from `core.py`;
  nothing threshold-like is re-derived. The v1 `cap` field is display/ledger
  truth; the *class* keeps the numeric gate for reducer parity, and the
  ledger flags any region where the two disagree.
- **Drill-down embeds one sample per unit**; other samples are one driver
  rerun away (`--sample-offset <i> --sample-count 1`), bit-reproducible per
  the chunkable-driver contract (`docs/STREAMING.md`).
- **Legacy mode** (`--legacy`): `library_versions` is `[]`, and
  `cap_counts`/`exact_tie_count`/`nonfinite_count`/`totals.nonfinite_records`
  are `null` — *not measurable*, never zero (rendering a legacy run as
  "0 caps" would be the fail-open reading `docs/SCHEMA.md` forbids). A run
  ledger row states legacy mode. Records without ids (pre-v0.3) reduce to a
  `no_id_records` run row; an empty model renders the template's empty state.

## The HTML template

`tools/tracked_tools/view/template.html` (packaged with the wheel so a pip
install works without the repo checkout). `tracked-view` injects the view
model as an inline JSON `<script>` block (with `</` escaped); everything
else is static. Journal-derived strings are untrusted and only ever enter
the DOM via `textContent`.

Visual-encoding decisions (per the dataviz method; the palette is the
validated reference instance, both modes declared as CSS custom properties):

- **Signal class = identity ⇒ categorical color job.** Fixed mapping, never
  reassigned: `local_cancellation` → slot 1 (blue `#2a78d6`/`#3987e5`),
  `cancellation_cascade` → slot 2 (orange `#eb6834`/`#d95926`),
  `log_near_root` → slot 3 (aqua `#1baf7a`/`#199e70`). DAG nodes are an
  all-pairs adjacency form, which caps categorical slots at three — and the
  validator confirmed no 4-slot subset of the reference palette passes
  all-pairs in both modes (dark violet↔blue collapses to ΔE 1.9 under
  protanopia). So the two non-mechanism classes fold to neutral: `stable` =
  de-emphasis gray (context, not a series) and `atan2_saturation` = the
  same neutral plus its always-on cap badge (semantically right too: the
  reducer's note for it is "no genuine hotspot"). The three slots were
  re-validated with `--pairs all` against both surfaces (light: worst CVD
  ΔE 9.2, normal 24.0; dark: 9.4 / 20.9); aqua's sub-3:1 light contrast
  WARN is relieved by the mandated labels/tables. Every node carries its
  class as a text chip (ink tokens beside a class-colored swatch — text
  never wears the series color) and a fixed class legend appears in both
  views, so identity is never color-alone.
- **Status colors are reserved for genuine state**: the range-guard
  violation badge (critical) and nonfinite badge (serious), always icon +
  label. Cap and exact-tie badges are informational (muted ink + label).
  `stable` deliberately does NOT wear status-good: per the reducer it means
  "no elevated mechanism detected", not "downcast-safe".
- **Node size is an ordinal cue, not a readable magnitude**: height is
  sqrt-scaled and clamped to [28, 64] px (hit target ≥ 24px), and the exact
  `n` is printed in the node sublabel, the detail panel, and the regions
  table.
- **Hotspot meter = the ranking metric.** Digits lost ≈
  `clamp(16 + log10(max_rel_err), 0, 16)` on an explicit 16-digit track
  (double has ~15.95); `max_rel_err ≥ 1` renders the full track with an
  explicit "all digits" overflow label. `cond` is shown as text, never as
  the meter (a cascade is high-severity *because* rel_err is high while
  cond is low — a cond meter would contradict the rank).
- **rel_err decade histogram**: display domain clamped to decades
  [−17, 0] with labeled overflow bins (`<1e-17`, `≥1`; the right bin
  includes alarm-clamped nonfinite records), decade tick labels in ink
  tokens, single-hue sequential bars, per-bucket counts in the region
  detail table, and an "exact: k" count for `rel_err == 0` records that a
  log histogram cannot bucket.
- **Drill-down op DAG**: node fill = single-hue sequential ramp over
  `log10(cond)` with the ramp domain computed from *finite, uncapped* conds
  only; capped (`cap` present) and nonfinite nodes are excluded from the
  ramp and marked by icon + label badges; a scale bar states the domain.
  In-node text picks white/ink by fill luminance.
- **Tables are first-class, not fallback** (every chart's twin): a regions
  table, an edges table (region-level + function rollup), a per-drill-down
  ops table, and the ledger. Every tooltip value appears in one of them;
  all SVG nodes are keyboard-focusable (`tabindex`) with focus showing the
  same tooltip.
- Light + dark are separately *selected* steps from the reference palette
  (never an automatic flip), each validated against its own surface.
